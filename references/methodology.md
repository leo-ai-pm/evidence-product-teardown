# 产品类型与四层拆解方法

## 产品类型路由

先根据真实页面、代码或运行记录分类，不根据产品名猜测。混合产品可以采用主类型 + 次类型。

| 产品类型 | 识别证据 | 用户层重心 | 技术/模型层重心 | 数据层重心 |
|---|---|---|---|---|
| AIGC 创作工具 | 文本/图片/音频/视频生成、素材画布、模型参数、生成任务 | 从需求到成品的确认门、可控性、预览、修改成本、等待与费用 | 提示结构、专业 Agent 分工、模型/分辨率/时长、生成工具、质量验证、重试 | 项目配置、素材资产、引用关系、版本、生成任务、额度、下游失效 |
| 通用执行 Agent | 目标输入、计划、工具执行、跨应用动作、运行状态 | 授权感、计划可理解性、进度、暂停/接管、结果可信度 | 规划器、工具路由、权限、幂等、长任务、恢复、审计、完成验证 | 任务、步骤、工具调用、权限、运行事件、产物、检查点 |
| 对话陪伴产品 | 连续对话、人格表达、长期记忆、关系进展 | 情绪价值、人格一致性、边界、安全、记忆可控、依赖风险 | 对话策略、角色约束、情绪识别、记忆检索、安全与危机处理 | 用户偏好、记忆条目、关系状态、敏感数据、删除/更正/过期 |
| 传统软件/SaaS | 表单、列表、搜索、审批、协作、报表 | 信息架构、任务效率、错误恢复、协作与权限 | 业务规则、服务调用、状态流、集成、通知 | 业务实体、权限、审计、同步、一致性、导入导出 |
| 混合型 | 同时具备两类以上关键闭环 | 分别描述各子流程，再找共享决策门 | 找编排边界、能力归属和降级路径 | 找跨模块的统一 ID、状态、版本与权限 |

输出产品类型时包括：主类型、次类型、支持证据、反证/缺口、置信度。不要把 UI 风格或产品自称当作充分证据。

## 用户层

先还原“用户经历了什么”，不要从架构倒推体验。

检查：

- 用户最初目标、原始输入与补充材料；
- 第一次反馈和用户预期如何被建立；
- 每个操作、按钮、表单、选择项与默认值；
- 满意/继续、修改/回退、失败/重试、中断/恢复路径；
- 每一步的等待、费用、风险、控制感和可解释性；
- 结果是否真的存在、是否能预览/编辑/导出；
- 用户情绪只依据行为和反馈推断，使用“可能/推断”，不要诊断心理。

建议产物：时间线证据表、三泳道用户旅程（用户/界面/系统结果）、决策门与情绪曲线。

## 技术层

从可观察组件和状态入手，不预设微服务、消息队列或 Agent 数量。

检查：

- 页面、画布、任务中心、资产库、预览/编辑器的职责；
- Agent 出现顺序、触发者、接替者、重入条件和能力边界；
- 工具入口、公开工具结果、任务状态和错误；
- 状态机：等待、规划、确认、执行、验证、完成、失败、中断、重试、交接；
- 用户确认、权限、计费、幂等、并发、重试与取消；
- 聊天状态、任务状态、资产状态与页面投影是否一致；
- “计划调用”“实际调用”“工具成功”“状态写入成功”四者分开记录。

建议产物：Agent/组件清单、工具表、状态机、异常矩阵、交接图。

## 模型层

描述“为了复现可观察行为，模型必须做什么”，而不是猜内部模型或隐藏 Prompt。

每个模型/Agent 检查六类输入：

1. 用户当前输入；
2. 用户长期信息；
3. 项目全局上下文；
4. 上游输出；
5. 平台公共资产/规则；
6. 工具与运行时结果。

再记录：功能判断、缺失检查、确认门、自动继续条件、停止条件、工具选择、验证、修改与回退、完成条件、输出契约和下游交接。

需要功能等价 System Prompt 时，把规则分为【事实规则】【推断规则】【建议规则】【未知】；推导字段必须显式注明“语义化占位名/推导设计”。

## 数据层

为每个可观察对象建立数据字典，不把页面文案直接当真实数据库字段名。

至少检查：

- 实体/字段及真实名称或语义化占位名称；
- 生产者、消费者、读/写时机；
- ID、引用关系和是否稳定；
- 草稿、已确认、运行中、成功、失败、取消、过期/失效状态；
- 多版本、历史记录、覆盖策略和回滚；
- 上游修改后哪些下游对象必须标记 stale 或重新生成；
- 只写不读、只读不写、孤立资产和悬空引用；
- 聊天声明、任务状态和资产存在性之间的对账规则；
- 用户长期信息、隐私、删除与权限边界。

建议产物：全局字段表、实体关系/引用图、生产者—消费者矩阵、版本与失效规则。

## 跨层验证

对每个重要结果至少回答：

1. 用户做了什么？
2. 界面显示了什么？
3. 哪个组件/Agent 接管？
4. 哪个工具被实际调用，证据是什么？
5. 模型做了什么可观察判断？
6. 哪些数据被读取或写入？
7. 结果如何被验证？
8. 失败、中断或修改时如何恢复？

无法回答的环节不要补齐，放入验证清单。
