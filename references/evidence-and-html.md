# 证据协议与 HTML 交付规范

## 证据账本

| 字段 | 要求 |
|---|---|
| Evidence ID | 稳定且唯一，如 E-S01/E-P02/E-C03/E-L04 |
| 类型 | 截图、页面、录屏、代码、日志、接口、文档 |
| 来源位置 | 截图编号、URL+页面区域、文件+行号、日志时间 |
| 时间/顺序 | 真实时间优先；未知时记录相对顺序 |
| 原文/对象 | 按钮、Agent 名、字段、状态、错误、资产、代码符号 |
| 支持结论 | 只写证据直接支持的内容 |
| 限制 | 截断、同屏但不同时间、不可点击、权限不足等 |

禁止使用后期截图中的资产倒推早期步骤已经执行。区分：

- 页面有入口；
- Agent 说将执行；
- 页面显示执行中；
- 工具返回成功；
- 全局状态写入成功；
- 资产实际存在且能被下游引用。

这些是六个不同证据强度。

## 结论格式

每条关键结论写成：

`[结论等级] 结论文本。证据：E-S01、E-P03。限制：……`

推断必须能回溯至少一条事实；产品建议必须写清解决的证据化问题。无法确认时说缺什么证据，不只写“未知”。

## HTML 信息架构

默认报告使用以下顺序；若用户限定单一对象，可以收缩中间章节，但保留范围、证据、追溯和未知项。

1. 标题、目标与摘要；
2. 查看范围、操作边界与证据缺口；
3. 产品类型和拆解权重；
4. 证据索引；
5. 用户层；
6. 技术层；
7. 模型层；
8. 数据层；
9. 跨层流程/状态图/数据流；
10. 一致性冲突；
11. 事实、推断、未知与建议；
12. 产品机会点；
13. 最值得继续验证的问题；
14. 结论—证据追溯表。

## HTML 质量要求

- 单个 UTF-8 `.html` 文件，包含 `<title>`、一个 `<h1>` 和清晰的 `<main>`；
- 响应式布局，窄屏表格可横向滚动；
- 使用 CSS 变量区分事实、推断、未知、建议和风险；
- 页面有目录锚点，所有内部链接有效且 ID 唯一；
- 证据编号应可见，不藏在悬浮提示中；
- 大表格使用固定表头或滚动容器；
- 正常、修改、失败、中断路径在图中明确分支；
- 判断节点写条件，如“满意/不满意”“成功/失败”“继续/中断”；
- Mermaid 可用时保留源代码并提供文本/表格备份，避免 CDN 失败导致信息消失；
- 不嵌入敏感凭证、Cookie、Token、无关个人信息或大体积原始素材；
- 不写 TODO、示例占位文本或无法追溯的断言。

## 最终自检

- 所有用户要求的章节均存在；
- 每个重要结论至少有一个 Evidence ID；
- “Agent 已完成”已通过资产和状态验证，或明确标记未确认；
- 页面状态、任务状态、资产状态和聊天记录已经对账；
- 工具功能名未冒充官方名称；
- 推导设计没有伪装成当前产品实现；
- 产品类型决定了分析权重，但四层均已覆盖或明确说明未检查；
- 输出只有本轮范围，没有擅自继续拆其他对象。
